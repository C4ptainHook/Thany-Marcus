# ADR-0045: Composite note schema — notes, attachments, entities, mentions, projects, embeddings

Status: Accepted (drafted from 2026-05-18/19 grilling; implementation lands as a single migration before M5+)
Date: 2026-05-19

## Context

CLOUD-002 (composite ingest) shipped the initial `notes` / `attachments` /
`ingest_jobs` / `plugin_tokens` / `cloud_settings` schema on the user cloud.
That schema covered the bare-minimum capture-and-process flow but left
gaps that block the rest of the M5/M6 pipeline:

1. No place for the LLM's semantic vectors (used for retrieval, routing,
   entity dedup).
2. No place for extracted entities, mentions, hubs.
3. `notes.suggested_project` was a free string — no way to express that
   "ClientA" mentioned in a body refers to the same `Project` the note is
   routed to.
4. No tombstones for deletes (plugin can't reflect deletions in vault).
5. No idempotency guards on plugin retries / offline-queue drains.
6. No room for cross-note attachment deduplication.
7. No model for hub notes (which are dossier notes auto-generated by the
   cloud from entity mentions per `cloud-pivot-plan-2026-05-13.md §B4`).
8. No project lifecycle (create / edit / delete / soft-delete) consumable by
   the plugin.

The pipeline architecture ([[0042-cloud-ingest-pipeline-architecture]]),
model lineup ([[0043-cloud-side-model-lineup]]), and intelligence layer
([[0044-cloud-intelligence-layer]]) all reference schema shapes assumed by
this ADR. The composite-ingest decision (`memory/composite_ingest_decision.md`,
2026-05-17) constrains the data model to "one composite draft → one
processed note." The "one cloud per user" memory lock removes the need for
per-row tenant columns; everything in a cloud's DB belongs to that single
user.

The schema also has to support evaluation (M9): EVAL-002 routing accuracy,
EVAL-003 entity dedup P/R, EVAL-005 wikilink precision-at-K, EVAL-006 weekly
diary. Each metric reads rows from these tables; their shape has to be
queryable cleanly.

## Decision

A composite-note schema with **eight first-class tables**, three reused from
CLOUD-002 with additions, and five net-new. **Cloud is source of truth**;
the user vault is a projection rendered from `notes.body_output`. Plugin
mutates back via `/api/sync/push` for user edits. All vector retrieval uses
a single 256-dim text embedding space (per
[[0043-cloud-side-model-lineup]]).

Schema overview:

```
Existing (extended):
  notes               — capture-derived OR hub-generated; body_output is the user-visible artifact
  attachments         — raw inputs (url/image/audio/document/video/file) with extraction results
  ingest_jobs         — per-note pipeline orchestration (driven by [[0042]])

New for M5:
  extraction_tasks    — per-attachment sub-jobs (driven by [[0042]])

New for M6:
  entities            — people / organizations / projects / places / concepts
  mentions            — wikilink anchors connecting notes to entities

Pre-existing:
  plugin_tokens
  cloud_settings
```

### 1. `notes` — capture or hub, cloud-canonical

```
notes:
  id                    UUID PK                                   -- Guid v7
  client_note_id        TEXT NULL                                 -- plugin-issued idempotency key (UUID v7)
  captured_at           TIMESTAMPTZ NOT NULL                      -- when user committed in the plugin
  body_input            TEXT NOT NULL DEFAULT ''                  -- user-typed text
  body_output           TEXT NULL                                 -- assembled Markdown (post-compose phase)
  relative_path         TEXT NULL                                 -- where the plugin writes it in the vault
  status                TEXT NOT NULL DEFAULT 'pending'           -- pending|processing|ready|failed
  llm_mode              TEXT NULL                                 -- 'safe'|'unsafe'
  tags                  TEXT[] NULL                               -- LLM-extracted tags
  provenance            JSONB NULL                                -- per [[0042]] §10c; runs[] timeline
  embedding             vector(256) NULL                          -- Granite Matryoshka cut; computed post-compose
  is_hub                BOOLEAN NOT NULL DEFAULT false            -- true when this note is an entity hub
  project_id            UUID NULL FK→entities(id) ON DELETE SET NULL   -- routed project; entities.kind='project'
  hub_entity_id         UUID NULL FK→entities(id) ON DELETE SET NULL   -- set iff is_hub; the entity this hub is for
  deleted_at            TIMESTAMPTZ NULL                          -- soft-delete tombstone
  transition_version    BIGINT NOT NULL DEFAULT 0                 -- optimistic concurrency
  created_at            TIMESTAMPTZ NOT NULL DEFAULT now()
  updated_at            TIMESTAMPTZ NOT NULL DEFAULT now()

  UNIQUE INDEX ix_notes_client_note_id (client_note_id) WHERE client_note_id IS NOT NULL
  HNSW   INDEX ix_notes_embedding (embedding vector_cosine_ops)
  INDEX  ix_notes_updated_at (updated_at) WHERE deleted_at IS NULL OR status = 'ready'
  INDEX  ix_notes_project (project_id)
  INDEX  ix_notes_hub_entity (hub_entity_id) WHERE is_hub
```

Key behaviors:

| Aspect | Decision |
|---|---|
| Source of truth | Cloud-canonical. User edits in vault sync back via `/api/sync/push`. Hub regeneration overwrites `body_output`. |
| `body_input` vs `body_output` | `body_input` = user's typed text only; `body_output` = composed Markdown (body + attachment renders, with wikilinks). Re-processing changes only `body_output`. |
| `client_note_id` | Plugin-issued UUID v7. Server-side idempotency via UNIQUE partial index. Second `/init` with same value returns existing note + refreshed presigned URLs. |
| `embedding` | Granite Embedding 278m R2 @ 256 dim (Matryoshka cut). Computed during `embedding` phase from `body_output` (truncated to first 512 tokens). Recomputed on body change. NULL when note is pre-`embedding` phase. |
| `is_hub` + `hub_entity_id` | A hub is a Note that exists as an entity's dossier. Same table as capture notes — plugin pulls + writes to vault uniformly. |
| `project_id` | FK to `entities(id)` where `kind='project'`. Replaces shipped `suggested_project` string column. |
| `deleted_at` | Soft-delete tombstone (per [[0032-fk-cascades-and-soft-delete]]). Sync_pull surfaces tombstones; plugin moves vault file to `.trash/`. |

### 2. `attachments` — raw inputs and extraction results

```
attachments:
  id                     UUID PK
  note_id                UUID NOT NULL FK→notes(id) ON DELETE CASCADE
  client_attachment_id   TEXT NOT NULL                            -- per-note idempotency key
  parent_attachment_id   UUID NULL FK→attachments(id) ON DELETE CASCADE   -- for video keyframes/audio children
  kind                   TEXT NOT NULL                            -- 'url'|'image'|'audio'|'document'|'video'|'file'
  storage_provider       TEXT NOT NULL                            -- 's3' (DO Spaces)
  storage_bucket         TEXT NOT NULL
  storage_key            TEXT NOT NULL                            -- notes/<note-id>/attachments/<att-id>
  filename               TEXT NULL
  mime_type              TEXT NULL
  byte_size              BIGINT NULL
  sha256                 TEXT NULL                                -- hex SHA-256; powers extraction cache
  url                    TEXT NULL                                -- set only when kind='url'
  status                 TEXT NOT NULL DEFAULT 'pending'          -- pending|awaiting_upload|uploaded
  extraction_status      TEXT NOT NULL DEFAULT 'pending'          -- pending|extracted|skipped|failed
  extracted_text         TEXT NULL                                -- output of the extraction processor
  extraction_error       TEXT NULL                                -- when extraction_status='failed' or 'skipped'
  extraction_cache_key   TEXT NULL                                -- sha256:sidecar:model:version
  extra                  JSONB NOT NULL DEFAULT '{}'              -- EXIF, pHash, duration, etc.
  created_at             TIMESTAMPTZ NOT NULL DEFAULT now()
  updated_at             TIMESTAMPTZ NOT NULL DEFAULT now()

  UNIQUE INDEX ix_attachments_note_client (note_id, client_attachment_id)
  INDEX        ix_attachments_parent (parent_attachment_id)
  INDEX        ix_attachments_cache (sha256, extraction_cache_key) WHERE extracted_text IS NOT NULL
  INDEX        ix_attachments_note (note_id)
```

Key behaviors:

| Aspect | Decision |
|---|---|
| `kind` vocabulary | Six values (`url`, `image`, `audio`, `document`, `video`, `file`). String, not enum — adding values doesn't require migration. Dispatch logic in [[0043-cloud-side-model-lineup]] §"Per-kind dispatch". |
| `storage_key` | `notes/<note-id>/attachments/<att-id>` (or `…/keyframes/<i>.jpg` for video children). Cloud generates; never user-visible. |
| Hash-based extraction cache | Across notes: if a new attachment's `sha256` matches an existing row with same `extraction_cache_key`, the worker copies `extracted_text` + `extra` and skips the sidecar call. Cross-note dedup is free. |
| `extraction_cache_key` | Composite: `sha256:sidecar:model:version`. Model-version bumps invalidate correctly. |
| `parent_attachment_id` | For video decomposition (per [[0043]] §"Video as composite extraction"): keyframe + audio children link back to the video parent. CASCADE on parent delete. |
| `client_attachment_id` | Per-note idempotency. UNIQUE on `(note_id, client_attachment_id)`. Plugin retries with same ID return same attachment row. |
| `extra` JSONB | Per-kind structured metadata: image has `{exif, phash, blur}`; audio has `{duration_s, lang}`; document has `{page_count, has_tables}`; etc. Eval queries this for stage-specific metrics. |
| Failed / skipped attachments | NOT rendered in `notes.body_output` (per [[0042]] §4 best-effort + clean-vault policy). Plugin skips downloading their binaries on sync_pull. Binary stays in Spaces for potential reprocess. |

### 3. `ingest_jobs` — per-note pipeline orchestration

```
ingest_jobs:
  id                   UUID PK
  note_id              UUID NOT NULL FK→notes(id) ON DELETE CASCADE
  kind                 TEXT NOT NULL DEFAULT 'capture'             -- 'capture'|'hub_regen'|'reprocess'
  status               TEXT NOT NULL DEFAULT 'queued'              -- see [[0042]] §3 for full vocabulary
  attempts             SMALLINT NOT NULL DEFAULT 0
  last_error           TEXT NULL
  lease_owner          TEXT NULL
  lease_expires_at     TIMESTAMPTZ NULL
  scheduled_at         TIMESTAMPTZ NOT NULL DEFAULT now()
  started_at           TIMESTAMPTZ NULL
  finished_at          TIMESTAMPTZ NULL
  events_log           JSONB NOT NULL DEFAULT '[]'
  transition_version   BIGINT NOT NULL DEFAULT 0
  created_at           TIMESTAMPTZ NOT NULL DEFAULT now()
  updated_at           TIMESTAMPTZ NOT NULL DEFAULT now()

  INDEX ix_ingest_jobs_claim (status, scheduled_at)
    WHERE status NOT IN (terminal states — see [[0042]] §3)
  UNIQUE INDEX ix_ingest_jobs_active_per_note (note_id)
    WHERE status NOT IN (terminal states)
```

`status` vocabulary, retry policy, and state machine in
[[0042-cloud-ingest-pipeline-architecture]] §3. `kind` differentiates the
three job flavors (capture / reprocess / hub_regen) that share the same
state machine.

### 4. `extraction_tasks` — per-attachment sub-jobs

```
extraction_tasks:
  id                   UUID PK
  ingest_job_id        UUID NOT NULL FK→ingest_jobs(id) ON DELETE CASCADE
  attachment_id        UUID NOT NULL FK→attachments(id) ON DELETE CASCADE
  target_sidecar       TEXT NOT NULL                              -- 'ollama'|'docling'|'parakeet'|'url'|'video'
  status               TEXT NOT NULL                              -- 'queued'|'processing'|'succeeded'|'failed'|'skipped'
  attempts             SMALLINT NOT NULL DEFAULT 0
  last_error           TEXT NULL
  lease_owner          TEXT NULL
  lease_expires_at     TIMESTAMPTZ NULL
  scheduled_at         TIMESTAMPTZ NOT NULL DEFAULT now()
  started_at           TIMESTAMPTZ NULL
  finished_at          TIMESTAMPTZ NULL
  events_log           JSONB NOT NULL DEFAULT '[]'
  transition_version   BIGINT NOT NULL DEFAULT 0
  created_at           TIMESTAMPTZ NOT NULL DEFAULT now()
  updated_at           TIMESTAMPTZ NOT NULL DEFAULT now()

  INDEX ix_extraction_tasks_claim (target_sidecar, status, scheduled_at)
    WHERE status IN ('queued','processing')
  INDEX ix_extraction_tasks_job (ingest_job_id)
```

Specialist worker pool architecture per [[0042-cloud-ingest-pipeline-architecture]] §1.

### 5. `entities` — people / orgs / projects / places / concepts

```
entities:
  id                  UUID PK
  kind                TEXT NOT NULL                               -- 'person'|'organization'|'project'|'place'|'concept'|'other'
  canonical_name      TEXT NOT NULL                               -- display + matching name
  aliases             TEXT[] NOT NULL DEFAULT '{}'                -- alternative names
  description         TEXT NULL                                   -- LLM-auto-summary or user-supplied
  embedding           vector(256) NULL                            -- semantic retrieval (dedup, routing)
  hub_note_id         UUID NULL FK→notes(id) ON DELETE SET NULL   -- set when materialized as hub
  mention_count       INT NOT NULL DEFAULT 0                      -- denormalized counter
  source              TEXT NOT NULL                               -- 'user'|'llm'
  is_provisional      BOOLEAN NOT NULL DEFAULT false              -- LLM-auto-created, awaiting user confirmation
  vault_folder        TEXT NULL                                   -- where plugin places routed notes; meaningful for kind='project'
  deleted_at          TIMESTAMPTZ NULL                            -- soft-delete tombstone
  created_at          TIMESTAMPTZ NOT NULL DEFAULT now()
  updated_at          TIMESTAMPTZ NOT NULL DEFAULT now()

  UNIQUE       (kind, canonical_name) WHERE deleted_at IS NULL
  HNSW INDEX   ix_entities_embedding (embedding vector_cosine_ops)
  INDEX        ix_entities_kind_source (kind, source)
  CHECK        (source IN ('user', 'llm'))
```

Key behaviors:

| Aspect | Decision |
|---|---|
| Single table covers all kinds | `kind` is open vocabulary string (add new kinds without migration). `('person', 'John Smith')` and `('project', 'ClientA')` coexist. |
| `source='user'` vs `source='llm'` | User-created (via portal/plugin UI) vs LLM-auto-extracted. Different lifecycle: user-source projects auto-create hubs immediately; LLM-source need to cross the mention threshold (N=3). |
| `is_provisional` | True when LLM auto-creates a new entity; plugin UI surfaces a "Confirm or merge" affordance. User-source entities are non-provisional. |
| `aliases` | `text[]` directly. Avoids join table; thesis-scale justifies. Dedup LLM may add to this array during dedup decisions. |
| `description` | Free text. Used in routing prompt as context. Auto-populated by LLM on entity creation; user can override. |
| `embedding` | Granite Embedding 278m R2 @ 256 dim of `canonical_name + ' ' + description + ' aliases: ' + join(aliases)`. Powers pgvector top-K for dedup. |
| `hub_note_id` | Set when an entity has a corresponding hub note. Soft-delete-safe via FK SET NULL. |
| `mention_count` | Denormalized counter. Saga's `extracting_entities` phase increments per mention insert. The N=3 threshold check is a single SELECT. |
| `vault_folder` | Only meaningful for `kind='project'`. Tells plugin where routed notes belong. Defaults to `'Inbox/<canonical_name>'` for LLM-source projects until user promotes. |
| `(kind, canonical_name)` UNIQUE | Soft-delete-aware (WHERE clause). Prevents two `(person, "John Smith")` entries. Re-creating after delete is allowed. |

### 6. `mentions` — wikilink anchors

```
mentions:
  id                  UUID PK
  entity_id           UUID NOT NULL FK→entities(id) ON DELETE CASCADE
  note_id             UUID NOT NULL FK→notes(id)    ON DELETE CASCADE
  anchor_text         TEXT NOT NULL                                  -- literal text in body_output that triggered
  start_offset        INT NOT NULL                                   -- char offset (post-compose, pre-wikilink)
  end_offset          INT NOT NULL                                   -- exclusive
  confidence          REAL NULL                                      -- LLM confidence at extract time
  created_at          TIMESTAMPTZ NOT NULL DEFAULT now()

  INDEX ix_mentions_entity (entity_id)
  INDEX ix_mentions_note (note_id)
```

Key behaviors:

| Aspect | Decision |
|---|---|
| One row per occurrence | Multiple mentions of same entity in same note allowed. Each occurrence has its own row + offsets. |
| Offsets | Character positions in pre-wikilink body. Used by the wikilink-placement step in `extracting_entities` phase to replace mention spans with `[[Entity canonical_name]]`. |
| `confidence` | From the LLM's per-mention output. Sub-threshold mentions are not inserted (provenance records the rejection). |
| Re-extraction semantics | When a note's `body_output` changes (reprocess, user edit via sync_push), saga DELETEs all mentions for that note and re-extracts. CASCADE handles note deletion. |
| No soft-delete | Mentions are derived data; reset cleanly on re-extraction. |

### 7. Embeddings — column-on-table, not separate

Decision: a `vector(256)` column on `notes` and `entities` directly. **No
separate embeddings table** for thesis MVP. Reasons (per F5+F14 grilling):

- Single embedding model (Granite 278m R2 Matryoshka cut to 256 dim).
- Retrieval pattern is one-shot: `ORDER BY embedding <=> $vec LIMIT K`.
  No JOIN.
- HNSW index per table; default operator class `vector_cosine_ops`.
- Per-chunk embeddings for long bodies are a future-work hook (separate
  `note_chunks` table added later; no breaking schema change).

Truncation: bodies exceeding Granite's 512-token context are truncated for
embedding only; full `body_output` is preserved verbatim. Truncation recorded
in provenance.

### 8. Provenance — JSONB on `notes`

Provenance is a single `notes.provenance JSONB` per note holding run history
nested inside. Schema v1 per [[0042-cloud-ingest-pipeline-architecture]] §10c.
Trimmed to last N=5 runs to bound JSONB size; older runs garbage-collected.

Visibility to plugin: opt-in shadow tree at `.provenance/<note-id>.json`.
Plugin pulls `provenance` field in sync_pull response; if user enabled
"Mirror provenance" in plugin settings, writes the file. Default: OFF.

### 9. Sync model — cursor, tombstones, push

**Cursor**: `updated_at` timestamp. Sync pull:
```sql
SELECT * FROM notes
WHERE updated_at > $since
  AND (status = 'ready' OR deleted_at IS NOT NULL)
ORDER BY updated_at
LIMIT $page_size
```
Plugin sends `?since=<ISO>`; server returns `nextSince = max(updated_at)`.

**Tombstones**: `notes.deleted_at` soft-delete. Plugin sees rows with
`deleted_at != null` and moves the vault file to `.trash/`.

**Sync push** (user edits):
```
POST /api/sync/push
{
  "noteId": "...",
  "body": "...",
  "baseUpdatedAt": "<what plugin saw at pull>",
  "deleted": false
}

→ 200  : applied; embedding recomputed
→ 409  : conflict (cloud advanced past baseUpdatedAt); plugin re-pulls
```
User edits become the new `body_output` verbatim — NO automatic
re-processing. Embedding always recomputed. Explicit reprocess is a separate
endpoint per [[0042-cloud-ingest-pipeline-architecture]] §6.

**Projects in sync_pull**: every sync_pull response includes a `projects[]`
section with entities updated since `since` (kind='project', including
tombstones). Plugin caches the project list locally.

### 10. Project management endpoint surface

Plugin-callable, bearer-auth:

```
GET   /api/sync/pull             — already shipped; extended to include projects[]
POST  /api/sync/push             — user edits flow back here
POST  /api/sync/events           — SSE stream for progress (per [[0042]])
POST  /api/admin/projects        — create user-source project entity
PATCH /api/admin/projects/{id}   — edit canonical_name / aliases / description / vault_folder
DELETE /api/admin/projects/{id}  — soft-delete (entities.deleted_at = now())
POST  /api/notes/{id}/reprocess  — re-run pipeline (per [[0042]] §6)
DELETE /api/notes/{id}           — soft-delete (notes.deleted_at = now()); cancellation path
```

Hub regen for user-source projects fires automatically on create (per F9
auto-hub). Delete cascades correctly: `notes.project_id` is FK SET NULL;
existing notes lose their project assignment but stay in their old vault
folders.

### 11. Idempotency contract (re-stated for completeness)

- `notes.client_note_id` — UNIQUE partial index. Plugin retries `/init` with
  same value get back the same `note_id` + refreshed presigned URLs.
- `attachments.(note_id, client_attachment_id)` — UNIQUE. Plugin retries
  with same composite key get back same `attachment_id`.
- `ingest_jobs.(note_id) WHERE status NOT IN (terminals)` — UNIQUE.
  Prevents concurrent capture / reprocess / hub_regen on the same note.

### 12. Soft-delete coverage

| Table | Soft-delete column | Behavior |
|---|---|---|
| `notes` | `deleted_at` | Surfaced in sync_pull as tombstone; cancels in-flight saga at next phase boundary |
| `entities` | `deleted_at` | Surfaced in projects[] section of sync_pull; notes with `project_id` pointing here get SET NULL |
| `attachments` | none | CASCADE on note delete |
| `mentions` | none | CASCADE on entity or note delete |
| `ingest_jobs` | none | Stay as historical record (terminal states preserved) |
| `extraction_tasks` | none | CASCADE on ingest_job delete |

### 13. Tags and metadata

`notes.tags TEXT[]` — flat list of LLM-extracted tags. No `tags` table for
MVP; thesis scale doesn't justify normalization. Could promote tags to a
join table in M7+ if eval needs per-tag aggregation.

## Migration plan

Single EF migration `AddCompositeIngestSchemaV2` (or similar name; bumps the
cloud DB to schema_version 2). All changes apply atomically. Migration body:

```sql
-- 1. Required extension
CREATE EXTENSION IF NOT EXISTS vector;

-- 2. NEW: entities
CREATE TABLE entities ( ... -- see §5 );

-- 3. NEW: mentions
CREATE TABLE mentions ( ... -- see §6 );

-- 4. NEW: extraction_tasks
CREATE TABLE extraction_tasks ( ... -- see §4 );

-- 5. ALTER: notes
ALTER TABLE notes ADD COLUMN embedding          vector(256) NULL;
ALTER TABLE notes ADD COLUMN deleted_at         TIMESTAMPTZ NULL;
ALTER TABLE notes ADD COLUMN is_hub             BOOLEAN     NOT NULL DEFAULT false;
ALTER TABLE notes ADD COLUMN project_id         UUID        NULL REFERENCES entities(id) ON DELETE SET NULL;
ALTER TABLE notes ADD COLUMN hub_entity_id      UUID        NULL REFERENCES entities(id) ON DELETE SET NULL;
ALTER TABLE notes ADD COLUMN transition_version BIGINT      NOT NULL DEFAULT 0;
ALTER TABLE notes DROP COLUMN suggested_project;
CREATE UNIQUE INDEX ix_notes_client_note_id ON notes(client_note_id) WHERE client_note_id IS NOT NULL;
CREATE INDEX ix_notes_embedding ON notes USING hnsw (embedding vector_cosine_ops);
CREATE INDEX ix_notes_updated_at ON notes(updated_at) WHERE deleted_at IS NULL OR status = 'ready';
CREATE INDEX ix_notes_project ON notes(project_id);
CREATE INDEX ix_notes_hub_entity ON notes(hub_entity_id) WHERE is_hub;

-- 6. ALTER: attachments
ALTER TABLE attachments ADD COLUMN parent_attachment_id UUID NULL REFERENCES attachments(id) ON DELETE CASCADE;
ALTER TABLE attachments ADD COLUMN extraction_cache_key TEXT NULL;
ALTER TABLE attachments ADD COLUMN url                  TEXT NULL;       -- previously stored in extra; promote
CREATE UNIQUE INDEX ix_attachments_note_client ON attachments(note_id, client_attachment_id);
CREATE INDEX ix_attachments_parent ON attachments(parent_attachment_id);
CREATE INDEX ix_attachments_cache  ON attachments(sha256, extraction_cache_key) WHERE extracted_text IS NOT NULL;

-- 7. ALTER: ingest_jobs
ALTER TABLE ingest_jobs ADD COLUMN kind               TEXT NOT NULL DEFAULT 'capture'
  CHECK (kind IN ('capture','hub_regen','reprocess'));
ALTER TABLE ingest_jobs ADD COLUMN events_log         JSONB NOT NULL DEFAULT '[]';
ALTER TABLE ingest_jobs ADD COLUMN transition_version BIGINT NOT NULL DEFAULT 0;
CREATE UNIQUE INDEX ix_ingest_jobs_active_per_note ON ingest_jobs (note_id)
  WHERE status NOT IN (terminal-state-list);
```

All ALTER TABLE columns are nullable or have defaults; the migration is safe
to apply on a populated DB (smoke clouds with existing notes don't break).

## Alternatives considered

### Note canonicality (F1)

| Option | Why considered | Why rejected |
|---|---|---|
| **Cloud-canonical (chosen)** | Re-processing, hub regen, multi-device sync all work; vault is a thin client | — |
| Vault-canonical | Pure capture pipeline; no sync-back machinery | Breaks hub regen (cloud can't materialize generated views into vault); multi-device sync impossible |
| Hybrid (phase-owned) | Clean handoff at status=ready | Complex contract for hub generated views that must flow back |

### Embeddings storage (F5)

| Option | Why considered | Why rejected |
|---|---|---|
| **Column-on-table (chosen)** | Simplest; one pgvector index per table; no JOIN | — |
| Separate `embeddings` table | Multi-model support; per-chunk embeddings | Premature for thesis MVP; only one embedding model in production |
| Per-chunk embeddings now | Long-doc retrieval recall | Premature; thesis-scale captures are short |

### Project model (F9)

| Option | Why considered | Why rejected |
|---|---|---|
| **Projects-as-entities (chosen)** | Unified mention graph; routing reuses entity dedup machinery; project hubs free | — |
| Separate `projects` table | Cleaner separation of user-defined containers vs emergent entities | Doubles hub-regen code; loses unified routing; wikilinks of project names get split logic |
| Strings only (`suggested_project TEXT`) | Simplest schema | Breaks mention → wikilink → hub graph; loses thesis-novel project hubs |

### Attachment kinds (F2)

| Option | Why considered | Why rejected |
|---|---|---|
| **Discriminated kinds + mime_type (chosen)** | Schema-explicit; clean dispatch logic; aliases handle plugin/cloud mismatch | — |
| Minimal + mime-driven dispatch | Smaller enum, fewer migrations | Dispatch logic gets messy; "what does kind=file mean?" is ambiguous |
| Processor-keyed kinds (`vlm`, `docling`, etc.) | Direct mapping to processors | Bakes processor choice into schema; swapping models requires data migration |

### Hub representation (F8)

| Option | Why considered | Why rejected |
|---|---|---|
| **Flag + FK on `notes` (chosen)** | Single table; uniform sync; "list all hubs" = WHERE is_hub | — |
| Separate `hubs` table | Cleaner separation | Adds JOIN to every "is this a hub?" check for no benefit |
| `notes.kind` discriminator | More extensible | Slight overkill; flag covers MVP |

### Idempotency (F12)

| Option | Why considered | Why rejected |
|---|---|---|
| **Idempotent first-write-wins (chosen)** | Standard pattern; safe retries; offline queue drains cleanly | — |
| Reject on conflict (409) | Forces client to track state precisely | Bad UX for retries; offline drain becomes complex |
| Last-write-wins (overwrite body) | Allow "amending a draft" | Dangerous — duplicate request reverts processed note to pending |

## Consequences

### Positive

- **One Postgres DB per cloud** holds everything: schema is dense but
  reachable in a single `pg_dump`. Multi-table queries via standard JOINs.
- **Cloud-canonical** unblocks hub regen, multi-device sync, reprocess. The
  vault becomes a thin client; user can rebuild from scratch by reseeding
  from `/api/sync/pull?since=0`.
- **Single embedding space** (Granite 278m R2 @ 256 dim) unifies retrieval
  for routing, entity dedup, related-content. One pgvector index per table.
- **Projects-as-entities** lets the mention → wikilink → hub graph treat
  projects uniformly. User mention of "ClientA" in a note body wikilinks to
  the project's hub note — same code path as person/concept mentions.
- **Idempotency at every layer**: `client_note_id`, `client_attachment_id`,
  active `ingest_jobs.note_id`. Offline queue drain, network retries,
  network glitches all safe.
- **Soft-delete** propagates cleanly through CASCADE for derived tables
  (mentions, extraction_tasks) and SET NULL for first-class references
  (notes.project_id).
- **Hash-based extraction cache** (cross-note, model-aware) makes reprocess
  with same model effectively free.
- **Schema supports eval directly**: EVAL-002 routing accuracy reads
  `notes.project_id`, EVAL-003 entity dedup reads `mentions JOIN entities`,
  EVAL-005 wikilink precision reads `mentions.confidence` + LLM rationale
  in provenance.

### Negative / accepted costs

- 8 tables is more schema than the CLOUD-002 cut. Migration is one block,
  but the surface area for bugs is higher.
- `entities` + `mentions` + `notes` form a cyclic FK (notes.project_id →
  entities.id; entities.hub_note_id → notes.id). EF Core handles this with
  explicit FK configuration; insert order matters in tests. Migration
  must order CREATE TABLE for `entities` before adding FKs on `notes`.
- `notes.provenance` JSONB unbounded growth requires trimming logic (last
  N=5 runs). Not enforced at DB level; saga code prunes on each run.
- `mentions` rows are derived data and regenerated on every body_output
  change. Theoretically lossy if re-extraction yields different mentions;
  acceptable because the old mentions are no longer relevant to the new
  body.
- `entities.aliases` as `text[]` is OK for thesis scale (likely < 100
  entities, < 10 aliases each) but doesn't index well. If aliases grow
  large, promote to a normalized join table.
- LLM-source provisional entities with `vault_folder='Inbox/<name>'`
  default could create folder sprawl if LLM creates many unique entities.
  Plugin UI exposes "Confirm or merge" to prune.
- Tombstones in `notes.deleted_at` never get hard-deleted by MVP. Long-term
  DB growth; cleanup is M9 housekeeping.

### Operational

- All eight tables backed up via standard `pg_dump`. No external state
  beyond DO Spaces (which has its own versioning / lifecycle policies).
- HNSW indexes on `notes.embedding` and `entities.embedding` get rebuilt
  on pgvector version bumps. Acceptable downtime; ~seconds at thesis scale.
- The `(kind, canonical_name)` UNIQUE on `entities` with `WHERE deleted_at
  IS NULL` is a partial unique index — supported by Postgres but a quirk
  that test setups must replicate.

## Deferred future-work hooks

1. **Per-chunk embeddings** for long bodies (separate `note_chunks` table).
2. **Tags table** (normalize `notes.tags TEXT[]`) when eval needs per-tag
   aggregation queries.
3. **Aliases join table** if `entities.aliases` exceeds usable size for
   text[] indexing.
4. **Hard-delete vacuum job** for old tombstones (notes + entities older
   than 90 days with `deleted_at` set).
5. **Project merge** operation (M7+): combine two entities into one,
   migrate `notes.project_id`, archive the loser.
6. **Per-cloud schema versioning column** in `cloud_settings` so eval can
   filter notes by which schema version produced them.
7. **Snapshot endpoint** for plugin reseeding: `GET /api/sync/snapshot`
   returns the full corpus in one paginated response. Currently reseeding
   uses `?since=0` on `/api/sync/pull` which works but is slower.
